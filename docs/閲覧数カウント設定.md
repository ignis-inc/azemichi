# あぜみち 閲覧数カウント機能の設定手順

「どのページが何回見られたか」「PDF作成ボタンが何回押されたか」「/kicho・/boujo・/nisshiで記録が何回保存されたか」を、匿名で集計する機能です。利用者には表示されず、運営（河野さん）だけが `/admin/stats` で確認できます。

ログイン機能（`docs/ログイン設定.md`）とは別の独立した仕組みで、ログインしていない利用者のアクセスも数えます。

---

## 1. Supabaseにテーブルを作る（SQL Editorで1回だけ実行）

1. Supabaseの画面で「SQL Editor」を開く
2. `docs/analytics-setup.sql` の中身を全部コピーして貼り付け、実行する
3. これで次の4つができます
   - `analytics_events`（記録本体のテーブル。個人情報・IPアドレスは保存しません）
   - `analytics_totals` / `analytics_daily` / `analytics_monthly`（合計・日別・月別の集計ビュー）

## 2. `.env.local` に2つの値を追加する

`.env.local` に、すでに次の欄を用意してあります。

- `SUPABASE_SERVICE_ROLE_KEY` … 空欄になっているので、値を入れてください
  - Supabaseの「Project Settings → API」を開く
  - 新形式の画面なら **Secret key**（`sb_secret_...`）、旧形式（Legacy）なら **service_role** キーをコピーして貼る
  - ⚠️ このキーは全データを読み書きできる強い権限です。人に見せたり、`NEXT_PUBLIC_`を付けたりしないでください
- `ADMIN_STATS_PASSWORD` … 自動で仮のパスワードを入れておきました。そのままでも、お好きな文字列に変えても大丈夫です

保存したら、開発サーバーを再起動してください。

## 3. 本番（Netlify）にも登録する

Netlifyの「Site settings → Environment variables」に、次の2つも追加します。

- `SUPABASE_SERVICE_ROLE_KEY`
- `ADMIN_STATS_PASSWORD`

（`NEXT_PUBLIC_SUPABASE_URL` と `NEXT_PUBLIC_SUPABASE_ANON_KEY` は、ログイン機能の設定ですでに登録済みのはずです）

---

## 使い方

- `/admin/stats` を開き、`ADMIN_STATS_PASSWORD` の値を入力すると、集計画面が開きます
- 上部のタブで「ページ閲覧」「書類作成」「記録保存」を切り替えられます
- 対象（ページ／ツール）ごとの合計表、直近30日の日別グラフ、直近12か月の月別グラフを確認できます
- 「ロックする」を押すと、また入力画面に戻ります

検索エンジンには載らないようにしてあります（`robots.txt` で除外・`noindex`設定）が、URLを知っていれば誰でもパスワード入力画面までは開けます。パスワードは他人に共有しないでください。

## 記録しているもの・していないもの

**記録する**：どの画面を見たか（ページのパス）／どの書類のPDFを作成したか／どのツールで記録を保存したか、それぞれの回数と日時だけ

**記録しない**：IPアドレス・氏名・メールアドレスなど、個人を特定できる情報は一切保存しません
