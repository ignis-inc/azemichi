# あぜみち ログイン機能の設定手順

記帳（/kicho）・農薬肥料記録（/boujo）・農作業日誌（/nisshi）・ダッシュボード（/dashboard）の
ログイン版を動かすための、Supabase（サーバー）側の準備手順です。

書類作成系の9ツールや紹介ページはログイン不要のままで、この4つだけがログイン必須になります。

---

## 1. Supabaseプロジェクトを用意する

1. https://supabase.com にログインする
2. 新しいプロジェクトを作る（名前は例：`azemichi`）
   - ※既存の未公開プロジェクトを使い回すこともできます。その場合、ログイン機能は
     「auth」という専用の場所を使うので、そのプロジェクトの既存のデータ（テーブル）には
     影響しません。
3. 数分待つと使えるようになります

## 2. 接続情報を `.env.local` に貼る

1. Supabaseの画面で「Project Settings（歯車）→ API」を開く
2. 次の2つをコピーして、プロジェクト直下の `.env.local` に貼り付ける
   - **Project URL** → `NEXT_PUBLIC_SUPABASE_URL`
   - **Project API keys の anon public** → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
3. 保存して、開発サーバーを再起動する（`.env.local` は再起動しないと反映されません）

`.env.local` はGitに含まれない（公開されない）ので、キーを貼っても安全です。

## 3. ログイン方式とメールの設定（Supabaseの画面）

「Authentication（認証）」の設定で以下を確認します。

- **メール＋パスワード**が有効になっていること（初期状態で有効です）
- **URL Configuration**（リダイレクト先の許可リスト）に次を追加する
  - `http://localhost:3010/**`（手元での動作確認用）
  - 本番のURL（例：`https://azemichi.netlify.app/**`）
  - ※パスワード再設定メールのリンクが、ここに登録したURLにしか戻れないためです
- **メール確認（Confirm email）** について
  - 有効（初期状態）：新規登録すると確認メールが届き、リンクを開くと登録完了
  - 無効：登録した瞬間にログイン状態になる（動作確認がラクなので、テスト中は無効でも可）

## 4. 本番（Netlify）にも接続情報を入れる

Netlifyの「Site settings → Environment variables」に、`.env.local` と同じ2つを登録します。

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`

登録後に再デプロイすると、本番でもログインが使えるようになります。

---

## 動作の確認ポイント

- ログインしていない状態で `/kicho`・`/boujo`・`/nisshi`・`/dashboard` を開くと、`/login` に案内される
- `/login` で新規登録 → ログイン → 4ツールが開けるようになる
- 4ツールの上部の「ログアウト」で、また `/login` に戻る
- 「パスワードを忘れた方はこちら」→ メールのリンク → `/reset-password` で再設定できる

## 今回やっていないこと（次回対応予定）

- 各ツールのデータをクラウドに保存する機能
- 無料版（ログインなし）で貯めたデータの引き継ぎ

現時点では、ログイン・ログアウト・パスワード再設定までの「土台」だけを用意しています。
データは従来どおり、その端末のブラウザ（localStorage）に保存されます。
